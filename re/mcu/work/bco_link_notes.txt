1. PHYSICAL LINK
----------------
SPI0 master, fixed peripheral NPCS2.                                                          [H]
  pins: PA13 SCK(A), PA11 MISO(A), PA12 MOSI(A), PA09 NPCS2 (func B) -- table {pin,func} @0x8000d8a5
  MR   = 0x00030011 (MSTR=1, MODFDIS=1, PS=0 fixed, PCSDEC=0, PCS=0011 -> NPCS2, DLYBCS=0)  .data RAM 0x84
  CSR2 = 0x00000F09 (CPOL=1, NCPHA=0 => SPI mode 3, CSAAT=1, BITS=8, SCBR=15, DLYBS=0, DLYBCT=0) .data RAM 0x80
  SCK = PBA/15. CPU "FAST" = 66 MHz (PLL0 12 MHz x11 /2), PBA undivided => ~4.4 MHz.      [M: PBA div not 100% checked]
  (The "STBY: SPI speed: %d" print at 800100e0 prints 50000/400000 = TWI speeds, not SPI0.)
  CS is driven manually around each transaction (spi_select 8001a0f8 / unselect 8001a14e).
Module power enable  = PA04 (gpio 4), active high.                                            [H code, M naming]
Module reset         = PA17 (gpio 0x11), active low (driven low = reset, high = run; left as input when off). [H/M]
Module request line ("BCO IRQ") = PA20 (gpio 0x14), LEVEL polled, HIGH = module has queued data.  [H]
  No pin-change interrupt is used by the app for PA20 (only gpio_get at 8000cc8a/cd1e/cdf6).
No boot-mode/strap pins are driven by the app.                                                [H, within app]

Power-up (voActivateModuleTask 8000dd58, ticked from dmhBcoMgr_voTask):                        [H]
  init (8000da88): PA17=0, PA04=0.
  attach request (8000e160 -> event 0x1000000, state 1):
   S1: PA04=1 (power on); wait 1200 ms
   S2: PA17=1 (release reset); gpio pins -> SPI func; write CSR2, MR; SPI enable; wait 200 ms
   S3: start register-access task, IRQ task (IHS_START), WifiSetup, PlayStatus, SiteSurvey; bus-free=1;
       notify id 0 (attached); state 4 (RUN)
  IRQ task start: wait 1000 ms, then wait for PA20=1, then poll reg 0x11 (DM1000Status) until b0 in 0x20..0x25.
       b0=0x21 -> module app ready (status word 0x2100): notify id 2; WifiSetup proceeds (reads version regs etc).
       b0=0x23 -> treated like ready, plus notify id 5 (ZD1: LED mode 0x16, ZD1 event 0x40000) [M: update/BSL mode]
       other / timeout -> retry every 20 / 300 ms.
  Detach (dd58 state5/6, from 8000e370, 8000db30 path):
       (graceful: WifiSetup S0x0B writes reg 0xE2 = 00 00, waits <=5 s for module IRQ reg 0xE2 with b0=1)
       PA17=0; wait 20 ms; PA04=0; SPI pins -> GPIO input; notify id 1 (detached).
  Emergency off (8000dcdc, used for standby/watchdog reset/UCH): SPI off, pins input, PA17=0, busy-wait 20 ms,
       PA04=0, PA17 -> input.
  Supervision (IRQ SM, timer "0x17"): 60 s without a successful transaction -> retry counter; >30 -> error:
       notify 0x24 (never got status, sys event 0x60000004) / 0x26 (after status) / 0x25 (after first IRQ read);
       if register access not locked -> power-off sequence. Heartbeat: re-read reg 0x11 every 3 s while idle.

2. SPI FRAMING (8000c050 / 8000c154 / 8000c2d4 / 8000c6ec)
-----------------------------------------------------------
Byte stuffing on every byte both ways:  0x27 -> 27 27,  0xFF -> 27 01.  0xFF = idle/no data.        [H]
MCU clocks 0xFF to receive; a received raw 0xFF = "nothing" (ercBcoSpiRead returns 0x420004).
Register type table (256 entries 'F'/'V'/'X' @0x8000a27c) decides the command:                     [H]
  F (fixed, 2 data bytes):  05 06 07 08 0c 11 28 29 2a 2b 30 31 32 34 35 36 37 3b 46 48 49 4a 4d 50 51 52
                            53 54 56 57 5a 5b 60 6a 6b 74 76 7a c7 c9 ca cc ce e2 e3
  V (variable length):      00 25 26 27 2c 2d 2e 2f 33 38 39 3a 3c 3d 3e 3f 40 45 47 4b 4c 4e 4f 55 58 59
                            5c 5d 5e 5f 61 62 63 64 65 66 68 69 6c 75 77 78 79 7b c8 cb cd cf d0 d1 dc dd e4
WRITE (one CS-low burst, no response read by MCU):                                                 [H]
  F: CS low, 00 reg b0 b1, CS high                    (b0,b1 = buf[0],buf[1])
  V: CS low, 02 reg lenLo lenHi data[len], CS high    (len <= 0x405)
READ:                                                                                              [H]
  CS low, (01|03) reg 00 00, CS high; wait 5 ms; CS low; clock 0xFF:
   skip until byte == request type (01/03)  [500 ms timeout]
   then skip until byte == reg              [500 ms]
   F: next 2 bytes = b0 b1                   V: lenLo lenHi (LE), then len data bytes (bytes beyond caller max dropped) [5 s]
  CS high.  Timeout -> 0x420022.  Return codes: 0 ok, 0x420020 queued, 0x420021 busy/pending, 0x420022 timeout.
  Module-side note: the module ACKs writes too ("type reg ..."); the MCU never reads that ack -- it is skipped
  by the "scan for type byte" logic of the next read. A replacement module must tolerate CS going high right
  after a write and must keep responses for reads until polled. [M]
16-bit values: MCU treats b0 as HIGH byte (e.g. status 0x2100 = b0 0x21, b1 0x00). The module report calls
  b0 "lo". Always think in wire bytes b0,b1.                                                         [H]
Concurrency: one access at a time; IRQ SM only runs when the access task is idle (RAM_0078[0]=1) and register
  access is not locked (RAM_0078[1]=0, dmhBcoMgr_boLockRegisterAccess). API reads/writes are only executed once
  module status == 0x2100 and the IRQ SM is in its idle state.                                      [H]

IRQ / notification handling (voBcoMgrHandleModuleIrqTask 8000ca5c):                                 [H]
  while PA20 high: read reg 0x0C (F) -> b0 = number of register with pending data (0 = none);
  read that register (V, max 0x406 bytes) and dispatch via table @0x8000b2b4 {u8 reg, u32 handler}:
   reg  handler   action
   11   8000b684  DM1000Status b0: 21 -> status 0x2100; 23 -> ev 0x10000010 (id 5); 25 -> ev 0x10000002 (id 7);
                  26 -> ev 0x10000008 (id 0x29); 27 -> ev 0x10000004 (id 8 => MCU powers module off and
                  watchdog-resets itself after 200 ms, observer #1 8001ebd2)   (only if b1 == 0)
   29   8000b60c  HCR Status: b0=22 -> ev 0x10010000; 2020/2120 -> ev 0x10004000; 214E ignored; else 0x10008000 (NFU)
   2a   8000b5e0  DCR Ctrl: 2423 -> ev 0x12000000 (module asks host something; NFU/NetGetFile)
   2c   80008b40  XModem DM1 chunk accumulator (256-byte chunks, ev 0x10100000 at end)
   32   8000b518  NetStatus 2 ASCII bytes (see section 7)
   38   8000d1b4  IP address string (16) -> RAM "0.0.0.0" buffer
   40   8000b32c  same handler as E4 (AirPlay service callbacks, section 7)
   45   8000b458  Configuration (XML/Cne) reply ready -> ev 0x10200000
   58   8000d170  DeviceName (<=63 chars) -> notify 0x28 (ZD1 marks "name changed")
   5a   8000b470  ActiveWirelessProfile b0-'0' -> RAM_3edf, notify 0x21
   6a   8000b494  BssAttemptConnection / WPS+JBC progress (section 7)
   6b   8000be6c  "WiFi Off/On": b0==2 && b1!=0 -> notify 0x27(signed b1)  [L: signal level?]
   e2   8000b438  RebootDeviceStatus b0==1 -> ev 0x20 (module ready to be powered off)
   e3   8000b800  AirTunesPlaybackStatus b0 -> service cb3 (DACP command ack, section 3)
   e4   8000b32c  VolumeHostChange [svc][param][x][val] -> service callbacks
  Reads that are not in the table are consumed and dropped.

3. HCR / DRC CODES
------------------
HCR = write reg 0x28 "HCR Ctrl" (F) with b0=code>>8, b1=code&0xFF; status comes back by IRQ on reg 0x29. [H]
DRC = write reg 0x48 "DRCCommand" (F) with b0=code, b1=0. (BridgeCo "DRC" remote-control key codes.)       [H]
 Code         sent by                         trigger / meaning                                        conf
 HCR 0x2520   80008ba0 (XModem/NetGetFile)     cmd 0x25 = file transfer over XModem regs               H/M
 HCR 0x2421   WifiSetup S16 (80009cd0)          factory reset (FRS 80026a3e -> 8001e754 -> 800093fc,   H/M
              then notify 0x19 -> detach        event 0x2000): cmd 0x24 arg 0x21 = reset module settings
 DRC 0x9D     JBC S6 (8000997e)                 start JBConnect after Cne JBCSSID set                    H/M
 DRC 0x9F     JBC S7 (8000994a)                 stop JBConnect (on stop request ev 8)                     H/M
 DRC 0x9E     WifiSetup S17 (80009cb6)          ev 0x10 from main (8002 5cfa/5f96) when NetIF "wireless"  M/L
              selected -> notify 0xD -> sys event 0x70002000          [L: restart wireless / setup mode]
 DRC 0xDE     8001f150 (via 8001f00c)            expects AirTunesPlaybackStatus(0xE3) b0=1  [M: AirPlay pause]
 DRC 0xDF     8001f150 (via 8001f050)            expects 0xE3 b0=0                         [M: AirPlay play/resume]
 DRC 0xE1     8001ed74 (via 8001ecec)            expects 0xE3 b0=4, then sys event 0x70010000 [L: release/stop session]
 DRC 0xE2     8001ed74 (via 8001ed30)            expects 0xE3 b0=5                         [L: re-acquire session]
              (each: send, wait up to 3 s for the ack, resend every 2 s; used on source change away from/to
               Wifi and on standby entry; main dispatcher 800248bc calls 8001ecec/ed30/f00c/f050)
 DRC 0xB0     ev 0x10000200 (8000b404, key action 0xB in 800248bc)     [L: HID-style Play]
 DRC 0xB1     ev 0x10000400 (8000b3e8, key action 0xC)                 [L: Pause]
 DRC 0xB3     ev 0x14000000 (8000b420, key action 0xA)                 [L: next / FF]
 DRC 0xB2, 0x13, 0xFA  table entries (ev 0x11000000/0x10800000/0x10400000) -- no setter found in this build.
 (DRC table: 6 x {u32 event, u8 code} @0x8000d9f0, processed in dmhBcoMgr_voTask 8000e19c; at most one per tick.)
 Module-side HCR meanings (module app handler 0x602f7310): 0x20 notify, 0x21 reboot to BSL for update, 0x22 check
 online/USB, 0x23 flash fw in RAM, 0x24 restart/settings, 0x25/0x26 file transfer. HCR status 0x29: 2020 ok, 2121 fail.

5. NFU / XMODEM / NetGetFile / DFU
----------------------------------
XMODEM (voBcoMgrXmodemTask 80008ba0): MCU is RECEIVER, module sends.                                  [H]
 MCU -> module: 1-byte writes to reg 0x2D: 'C' (CRC start), ACK 06, NAK 15, CAN 18 x3 (300 ms apart).
 module -> MCU: IRQ-signalled reads of reg 0x2C, accumulated in 256-byte chunks (80008b40); short chunk = end.
 Packet [SOH|STX][blk][~blk][128|1024][CRC16-CCITT hi lo, init 0] (SOH <= 0x84 bytes: 8-bit sum).
 EOT: first NAKed, second ACKed. GET_FILE mode first sends HCR 0x2520.
NFU task (8000aca4/8000af1c): watches HCR status 0x29 and DCR 0x2A=2423 then would call XModemReceive (800091e4),
 but its callback/size are never set and its start state is never requested => DEAD CODE in this build.  [H]
 => The app never receives files from the module and never sends firmware TO the module.
USB DFU "flash-coproc" is NOT in the app (USB = UAC1+HID only; no DFU descriptors/strings). It is in the
 bootloader (0x80000000..0x80003FFF, docs/mcu/bootloader-dfu.md). App only checks/restores the ISP config word
 at 0x808001FC (0x929E0870). Module side: flash-coproc uses XModem-1K over regs 0x2D/0x2C
 then HCR 0x23/0x21 -- i.e. the BOOTLOADER is the XModem sender in that case.                         [H app / M BL]

6. FACTORY UART "UCH" (USART1 PA05 RX / PA06 TX, func A)  -- on this board the same lines are the module's console
   (UART1: PA06 -> RXD1, TXD1 -> PA05; measured 2026-10-23, docs/hardware/wiring.md)
-----------------------------------------------------------------------------------------------
Init 8000f7c0 (called by main SM when factory mode starts): 8N1 (MR 0x8C0); 115200 baud (57600 if
 80029454()==1 or 8001248c()==5); SLOW CPU mode: 2400. RX ISR 8000ea44 (IRQ 192) -> buffer RAM_7f50 (50 bytes).
Request:  [L][op][params...][CK]  L = count of bytes after L (op+params+CK); CK = (sum of L..last param) & 0xFF.
Reply ack: [04][op][ST][ERR][CK]  ST 00 accepted / FF rejected.  Data reply: [L][op][00][data...][CK].
Busy (byte arrives while executing): 04 00 FF 03 02 (non-standard CK).  Timeout -> err 9.
Errors: 3 busy, 4 checksum, 5 invalid opcode, 6 not implemented, 7 param too big, 8 invalid length, 9 timeout.

7. EVENT / MESSAGE FLOW
-----------------------
AirPlay service registration: 8000b70c(3, RAM_0c2c) -> service[3] = {cb0=8001e9ec, cb1=0, cb2=8001e774, cb3=8001e98c}.
Module -> MCU on reg 0x40 / 0xE4 (4 bytes [svc][param][x][val]):                                   [H decode, M meaning]
  svc 03 param 03 -> cb0(val) = 80013960 AirPlay volume -> MCU step:
        val 0x00..0xF0: step = 0x47 - ((val+3)*70/240)   (val 0 -> 71 = max, 0xF0 -> 1)
        val 0xF1..0xFF: step 0 (mute). Applied only when Wifi source active (else stored).
  svc 03 param 01 -> cb2(val): val 0 -> MCU replies W reg 0x40 = 03 01 01 02; val 3 -> replies 03 01 01 04
  svc 01 ...      -> second service slot (not registered in this build)
MCU -> module reg 0x40:
  03 03 01 vv   volume to AirPlay: vv = v*240/70 for v<=0x46, 0xFF if v>=0x47 (8001cf6c, sent by 8001dc84)
  03 01 01 02 / 03 01 01 01 / 03 01 01 04   play-state replies (8001e7b8; 01 has no setter found)   [M/L]
AirTunesPlaybackStatus (0xE3) -> cb3 8001e98c: 0 -> ack for DRC 0xDF; 1 -> ack 0xDE; 4 -> ack 0xE1 + sys 0x70010000;
  5 -> ack 0xE2.
Play status task (8000bccc): RAM_3ed4+0x448 set by XML on reg 0x47 (pl=2 play, pa=3 pause, em=1 empty) -> notify 0x16/0x17/0x18 (observer #1: Wifi status 3=playing
  sets RAM_7afc[8]=1, calls 8001efe4; 2=paused/stopped).                                              [M]
NetStatus (reg 0x32, b0 b1 ASCII): transitions of b1 '0'<->'1' -> notify 0x1A/0x1B, '0'<->'2' -> 0x1C/0x1D;
  b0!='0' && b1!='0' -> notify 0x1E (connected; observer #1 sets net state 2) else 0x1F (not connected).
  [L: b1 = interface '1' wireless / '2' wired, b0 = IP/link state]. WPS/JBC are only started when b1=='1'.
Wifi setup task after module ready: R 0x25, 0x26, 0x27, Cne GET "pssCne/CneId", Cne SET "SystemHost/HostVersion"
  (= MCU version string), R 0x32, notify 3, then idle loop reacting to events.                       [H]
WPS (ercHandleWpsTask): start = W reg 0x6C [RAM_005c[10]]"WPS_CFG" (PIN mode, ev 0x40) or "PB_CFG" (push button,
  ev 0x80) -> notify 0xE/0xF. Progress via reg 0x6A b1: '0'/'B' -> success (b0 stored, after 1 s notify 0x15 =>
  ZD1 writes reg 0x5A active profile); '1','2' -> 0x10; '3' -> 0x11; '4' -> 0x12; '5' -> 0x13; '6' -> 0x14;
  '@' (0x40) -> JBC "connected" event 4.                                                              [H decode, L meaning]
JBConnect (ercHandleJbcTask): SSID "ZeppelinAir_Setup_XXXXXX" (XXXXXX <- last 6 hex digits of reg 0x33 MAC),
  Cne SET "Networking/JBCONNECT/JBCSSID" = SSID, DRC 0x9D; wait reg 0x6A '@' or stop; stop = DRC 0x9F.   [H]
Source switch to Wifi: done locally (UCH op 0x8C p=4 / keys); module is told via DRC 0xE1/0xE2/0xDE/0xDF
  handshake (section 3); there is no "select input" register.                                         [M]
Standby: 8001029c -> if Bco enabled 8000dcdc (hard power-off). Network standby / wake from module not seen. [H/M]
Factory reset: MCU defaults, attach module, HCR 0x2421, notify 0x19 -> graceful detach; next attach restores
  network settings; user-page backup erased by 8001da70.                                              [M]
Module-requested reboot: reg 0x11 b0=0x27 -> MCU powers module off and resets itself through the watchdog.  [H]

Observer #1 (8001e9f8) id -> effect (RAM_7afc: [0] net state, [4] Wifi status 0..7, [8] AirPlay playing):
  0 attached [4]=1 | 1 detached [4]=0, sys 0x70000100 if factory reset pending | 2 ready sys 0x60000002 |
  3 info ready (fw compare 9112) sys 0x10002000 | 8 module reboot request -> MCU WDT reset | 0x16 playing [4]=3 |
  0x17/0x18 [4]=2 | 0x19 -> detach | 0x1B [4]=1 | 0x1E connected [0]=2,[4]=2 | 0x1F [0]=1,[4]=4 |
  0x20 sys 0x70000008 | 0x24 [4]=6 sys 0x60000004 | 0x25 [4]=7 sys 0x70000002 | 0x26 [4]=5 sys 0x70000004
Observer #2 (8001e134): 0 reset | 1 sys 0x60000040 | 5 LED 0x16 | 9 JBC on sys 0x60000008 | 0xB/0xC JBC off
  (0xC also sys 0x60000020) | 0xD sys 0x70002000 | 0xE/0xF WPS started (60 s timer) | 0x10-0x13 WPS fail/retry |
  0x15 WPS ok -> W reg 0x5A | 0x23 web-data request -> build XML -> W reg 0xDD

8. WHAT A REPLACEMENT MCU MUST DO TO DRIVE THE STOCK MODULE (minimum)
---------------------------------------------------------------------
- PA04=1, wait 1.2 s, PA17=1 + SPI on, wait 0.2 s + 1 s, then poll PA20 / read reg 0x11 until b0=0x21.
- SPI mode 3, ~4 MHz, 8-bit, CS low per request; 0x27/0xFF stuffing; read = header, CS high, 5 ms, CS low, clock 0xFF.
- While PA20 high: read reg 0x0C, then read the register named by b0 (drain queue). Re-read 0x11 every few s.
- Optional but used by stock: R 0x25/0x26/0x27, Cne set SystemHost/HostVersion, R 0x32; volume via reg 0x40
  [03 03 01 vv] both ways; play state via reg 0x47 XML and DRC 0xDE/0xDF (+0xE3 ack).
- Power-down: W 0xE2 = 00 00, wait for IRQ 0xE2 b0=1 (<=5 s), PA17=0, 20 ms, PA04=0.
