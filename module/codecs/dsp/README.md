# Shared fixed-point DSP

What the module's decoders share, in C that builds for the ARM926 and for Warp0 (integer only, no division, no
libc; an unaligned word access is avoided everywhere: on Warp0 it reads or writes the wrong bytes):

| File | |
|---|---|
| `imdct.c`, `imdct.h` | the IMDCT for N = 2048 and 256: an N/4-point complex FFT (radix 4, one radix-2 stage for 512 points) between pre- and post-twiddles, in block floating point. Used by module/codecs/aac and module/codecs/vorbis (the same transform: x[n] = sum X[k] cos(2 pi / N (n + N/4 + 1/2)(k + 1/2))), and so is `DSP_IMDCT_LONG_PAIRS`: a long block's samples in pairs straight from the FFT's output, for the one pass that does the reorder, both window halves and the overlap-add |
| `imdct_tables.c` | its twiddles and bit reversal, generated by `tools/gentables.py`; committed. `DSP_FAST` places them (Warp0: local RAM) |
| `fixed.h` | helpers: saturation, high-word multiplies, a rounded complex multiply step, clz, soft division; also module/codecs/flac's and Warp0's ALAC decoder's (`clz32`) |
| `rust/` | crate `zd1-dsp`: the IMDCT as one static library, so zd1-aac and zd1-vorbis link one copy |
| `check/imdctcheck.c` | the IMDCT against the formula in double precision: worst errors (0.7 LSB for loud low-frequency blocks) |

Moved out of module/codecs/aac unchanged: the AAC decoder's output is bit-identical before and after (1,293 frames of the
benchmark stream, host build and the Warp0 image under the emulator) [2026-10-25].
