# Vorbis decoder (fixed point)

Our decoder for what Spotify Connect sends (Ogg Vorbis 96-320 kb/s, 44.1 kHz stereo): raw Vorbis packets in (the
Ogg layer is the caller's), 16-bit PCM out. Written from the Vorbis I specification; where it leaves a choice it
does what libvorbis does. Integer only, no division in the per-packet paths, no libc and no malloc (the setup goes
into arenas the caller gives), every index that depends on the stream checked: the same C runs on the ARM926 and
on Warp0 (`module/warp0`, the Vorbis image), where a wild access can hang the bus.

| File | |
|---|---|
| `vorbisdec.c`, `vorbisdec.h` | the decoder (~1,000 lines): headers, codebooks (Huffman tables, lattice and explicit VQ), floor 1, residues 0/1/2, mappings with coupling, the long/short window overlap (libvorbis's rules) |
| `vorbis_tables.c`, `vorbis_tables.h` | floor 1's inverse dB table (the specification's) and the window slopes, Q31; generated by `tools/gentables.py`; committed |
| `rust/` | crate `zd1-vorbis`: the decoder for Rust (zd1-spotify's ARM decoder) |
| `check/` | `vorbischeck.c` on an Ogg file or its packets: `dump`, `cmp` (against a reference decoder's raw output), `packets` (for the Warp0 checks), `fuzz` (mutated packets and setups under ASan/UBSan), `bench` (speed on the unit); `corpus.py` (the comparison over a test corpus encoded by libvorbis) |

The IMDCT is module/codecs/dsp's, shared with the AAC decoder (Vorbis's MDCT is the same transform; its block sizes for
44.1 and 48 kHz are AAC's 256 and 2048).

## Numbers
Residue vectors are int32 with `rp` fractional bits, chosen per stream from the bounds of its residue books (every
cascade sum fits, with room for coupling: 9-13 for libvorbis's q0-q10). Codebook values are computed once at that
point: lattice books (lookup type 1, libvorbis's residue books: up to 6,561 entries x 8 dimensions) keep only their
few values, and a vector's digits come from a reciprocal multiply at decode time instead of a 210 KB table. The
floor curve is the inverse dB table in Q31, applied line by line as it is rendered; the spectrum goes to the IMDCT as
X * 2^(16 + log2 N), PCM Q9 out of it, Q8 after the windows, rounded to 16 bits. Long-long blocks (most of them) fold
the IMDCT's reorder, both window halves and the overlap-add into one pass, as module/codecs/aac does.

Setup memory: 70-110 KB for libvorbis's streams (Huffman tables with an 8-bit first level, the books' values, the
floors' and residues' structures). Not supported (vorbis_init says VORBIS_EUNSUP): floor 0 (no encoder has used it
since 2002), block sizes other than 256/2048 (libvorbis's q-1 at 44.1 kHz uses 512/4096; Spotify's lowest rate,
96 kb/s, is q2), more than two channels.

## Checked [2026-10-25]
- **Against libvorbis** (`check/corpus.py`: `oggenc` 1.4.3 at q0-q10 and managed 96/160/320 kb/s, stereo and mono,
  44.1 and 48 kHz, signals: music-like, sweep near full scale, clipped square, white noise, -60 dB and silence
  (unused floors), uncorrelated stereo, speech): every stream the exact length (trimmed to the last granule
  position), maximum difference 1-3 LSB, RMS 0.03-0.43 LSB from libvorbis's float decoder. The 0.4 LSB streams are
  the near-full-scale ones: the shared IMDCT's block floating point (module/codecs/aac's README shows the same).
- **Tools exercised**: residue types 1 (mono) and 2 (stereo), coupling, unused floors, long/short transitions in
  both directions (424-492 per 30 s on the benchmark files), end-of-stream trimming. Not exercised: residue type 0
  (no current encoder writes it), the end-of-packet rules inside a partition (no valid stream ends early).
- **Robustness**: ~860,000 mutated packets and 700 mutated setups over seven streams under ASan/UBSan
  (`vorbischeck fuzz`: bit flips, truncation, random bytes, shuffled order, restarts): no fault, every result within
  bounds.
- **On the unit, ARM926** (`vorbischeck bench`, -O2): 20.4 % of the CPU for 320 kb/s stereo, 17.8 % for 160 kb/s; Tremor
  on the same files 23.7 / 19.1 % (the bring-up benchmarks, `module/os/bench` up to 54faca1; its time includes the Ogg layer). Setup 25-30 ms.
- **On Warp0, the unit**: bit-identical to the ARM build on every packet of the 320
  and 160 kb/s benchmark streams (1,965 / 1,839 packets) and a mono one; 36.9 % / 32.5 % / 14.8 % of Warp0's time
  at real time (5.6 ms per 320 kb/s packet); setup 70-80 ms. In the emulator (`module/warp0/tools/emu.py vorbis`) the
  same image matches the host build on all 1,965 packets with no access outside Warp0's memory.

## Building and running the checks
```
cc -O2 -DVORBIS_STATS -I. -I../dsp -o /tmp/vorbischeck check/vorbischeck.c vorbisdec.c vorbis_tables.c \
   ../dsp/imdct.c ../dsp/imdct_tables.c -lm
python3 -I check/corpus.py /tmp/vorbiscorpus /tmp/vorbischeck          # the libvorbis comparison (nix's vorbis-tools)
/tmp/vorbischeck packets FILE.ogg FILE.pkts                             # for emu.py vorbis
```
`check/vorbischeck.c` has every command and the fuzzer's and the unit's build lines in its first lines.
